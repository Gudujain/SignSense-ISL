# SignSense current UI — heuristic baseline

**Scope:** Phase 0 documentation only. No app behavior was changed. Ratings below use Nielsen's severity scale: 0 = not a usability problem; 1 = cosmetic; 2 = minor; 3 = major; 4 = usability catastrophe / blocks task. The observations in the brief are logged as **reported** unless corroborated by source or the live page. A severity is a review judgment, not a measured user-study result.

## Summary

The prototype contains the intended learning areas, but Practice exposes internal recognition status and still depends on a Submit click while the learner may need both hands. Several reported layout and guidance issues make the main practice loop difficult to understand or complete. Recommendations are present and populated in the inspected database state, but overlap with the Home recommendation. Recognition and reference content are explicitly marked experimental/unreviewed in parts of the interface; these caveats are repeated and often presented as technical jargon.

## Nielsen heuristic coverage

| Heuristic | Baseline assessment |
|---|---|
| 1. Visibility of system status | Status and diagnostics exist, but reported “active/no hand/frames” state mixes system activity with learner progress and technical counts. |
| 2. Match between system and real world | Practice uses ML terms and unreviewed reference guidance; a learner needs actionable, sign-specific cues. |
| 3. User control and freedom | Start/Submit/Cancel exist; reported clipping and lack of hands-free completion undermine control while signing. |
| 4. Consistency and standards | Shared shell exists, but header controls and curriculum labels/layout are reported cluttered or inconsistent. |
| 5. Error prevention | Tracking/no-hand is detected, but error prevention should make framing and recovery obvious; target/reference content needs expert validation. |
| 6. Recognition rather than recall | Reference image is reported too small, while Practice lacks reviewed pose cues. |
| 7. Flexibility and efficiency of use | Core submission requires a pointer action; no hands-free alternative is present. |
| 8. Aesthetic and minimalist design | Multiple jargon labels, diagnostics, repeated disclaimers, dense controls and Home/Recommendations duplication add cognitive load. |
| 9. Help users recognize, diagnose and recover from errors | Some text exists, but no consistent three-level feedback or concise recovery guidance is evident. |
| 10. Help and documentation | Project docs exist, but learner-facing help and educator-reviewed sign instructions are limited. |
